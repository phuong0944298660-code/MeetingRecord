## 1. 项目概述

### 1.1 项目背景
为提高会议效率，减少人工整理会议纪要的时间成本，开发一款智能语音会议纪要应用。用户上传会议录音后，系统自动识别不同说话人，生成结构化的会议纪要。

### 1.2 项目目标
- 自动化会议内容整理，节省80%人工整理时间
- 准确识别多说话人，区分不同发言者
- 智能提取关键信息（待办、决策）
- 提供友好的历史记录管理和检索

### 1.3 目标用户
- 企业会议组织者
- 项目经理
- 行政助理
- 需要记录会议内容的职场人士

## 3. 功能需求

### 3.1 用户管理模块

#### FR-001 用户注册
- **优先级**: P1
- **描述**: 新用户注册账号
- **输入**: 用户名、密码、邮箱
- **输出**: 注册成功/失败提示
- **校验规则**:
  - 用户名: 3-20位字母数字下划线
  - 密码: 6-20位，至少包含字母和数字
  - 邮箱: 符合邮箱格式

#### FR-002 用户登录
- **优先级**: P1
- **描述**: 用户登录系统
- **输入**: 用户名/邮箱、密码
- **输出**: JWT Token、用户信息
- **业务规则**:
  - 密码错误3次锁定15分钟
  - Token有效期24小时

#### FR-003 用户信息管理
- **优先级**: P2
- **描述**: 修改个人信息、密码
- **输入**: 新信息/新密码
- **输出**: 更新成功提示

### 3.2 录音上传模块

#### FR-004 文件上传
- **优先级**: P0
- **描述**: 上传会议录音文件
- **支持格式**: MP3, WAV, M4A, AAC, OGG
- **大小限制**: 最大500MB
- **功能要求**:
  - 拖拽上传
  - 进度条显示
  - 格式自动校验
  - 上传中断可重试

#### FR-005 上传预处理
- **优先级**: P1
- **描述**: 上传前的处理
- **功能要求**:
  - 计算音频时长
  - 生成音频指纹（用于去重）
  - 文件名规范化

### 3.3 会议纪要模块

#### FR-006 会议信息生成（飞书风格）
- **优先级**: P0
- **描述**: AI处理生成结构化会议纪要
- **输出内容**:
  - **会议概览**：会议整体概述（100-200字）
  - **会议统计**：
    - 会议时长
    - 参与人数
    - 待办事项数量
    - 各说话人发言时长占比
  - **话题分段**：3-6个主要话题，每个包含：
    - 话题标题
    - 时间范围
    - 详细总结（300-500字）
    - 关键要点（3-5条）
    - 参与说话人
    - 相关待办事项
    - 重要决策
  - **全局待办**：所有待办事项的汇总列表
  - **全局决策**：所有重要决策的汇总列表

#### FR-007 会议纪要保持
- **优先级**: P1
- **描述**: 允许用户编辑保存会议纪要
- **功能**:
  - 编辑会议标题
  - 修改待办事项（支持标记完成状态）
  - 补充决策内容
  - 切换会议纪要/逐字稿 Tab

### 3.4 说话人分离模块

#### FR-008 说话人识别
- **优先级**: P0
- **描述**: 自动识别不同说话人
- **技术方案**:
  - 主方案：pyannote.audio 说话人分离模型
  - 备选方案：基于停顿时间的简单分割
- **功能要求**:
  - 区分不同音色
  - 标注说话人（说话人00、01...）
  - 支持手动标记姓名
  - 说话人筛选（按人过滤显示）

#### FR-009 逐字稿优化
- **优先级**: P0
- **描述**: 优化原始转录内容
- **技术方案**：GLM-5 大模型语义优化
- **优化内容**:
  - 繁体中文转简体中文
  - 根据语义智能添加标点符号
  - 根据语义逻辑进行段落划分
  - 去除重复的语气词、口头禅
  - 保持原始语义，不做内容增删
- **处理流程**：
  1. Whisper 原始转录（繁简转换）
  2. GLM-5 大模型优化（语义断句+标点）
  3. 生成优化后的逐字稿

#### FR-010 按说话人展示
- **优先级**: P0
- **描述**: 按说话人分组展示内容
- **展示方式**:
  - 时间线形式
  - 说话人头像/标识
  - 可折叠展开
  - 高亮关键词

### 3.5 历史记录模块

#### FR-011 历史列表
- **优先级**: P0
- **描述**: 侧边栏展示历史会议
- **功能要求**:
  - 倒序排列（最新在前）
  - 显示标题+日期
  - 处理状态标识
  - 无限滚动加载

#### FR-012 搜索功能
- **优先级**: P1
- **描述**: 搜索历史会议
- **搜索范围**:
  - 会议标题
  - 会议摘要内容
  - 说话人名称
  - 待办事项内容

#### FR-013 删除功能
- **优先级**: P2
- **描述**: 删除历史会议
- **功能要求**:
  - 二次确认
  - 逻辑删除（可恢复）
  - 关联文件清理

## 8. 技术实现详情

### 8.1 音频处理流程

```
┌─────────────┐    ┌──────────────┐    ┌────────────────┐

                                              │
                                              v
┌─────────────┐    ┌──────────────┐    ┌────────────────┐
│  保存数据库  │ <-- │ 生成会议纪要  │ <-- │ GLM-5优化标点  │
│             │    │ (飞书风格)   │    │ (语义断句)     │
└─────────────┘    └──────────────┘    └────────────────┘
```

### 8.2 说话人分离实现

| 方案 | 技术 | 模型大小 | 准确度 | 适用场景 |
|------|------|----------|--------|----------|
| 主方案 | pyannote.audio | ~300MB | 高 | 多人讨论会议 |
| 备选 | librosa停顿检测 | 无需模型 | 中 | 简单对话场景 |

**处理逻辑**：
1. 优先尝试 pyannote.audio 进行精确说话人分离
2. 失败时自动回退到基于停顿时间的简单分割
3. 合并相邻同说话人段落，优化阅读体验

### 8.3 逐字稿优化实现

**Step 1 - Whisper 转录（Python）**：
- 使用 opencc-python 进行繁简转换
- 添加异常处理，确保转换失败不影响主流程

**Step 2 - 大模型优化（Java/KimiService）**：
- 调用 GLM-5 API 进行语义优化
- Prompt 要求：繁简转换 + 智能标点 + 语义断句 + 去除口头禅
- 优化失败时回退到原始转录文本

### 8.4 WebSocket 实时进度

| 阶段 | 进度范围 | 说明 |
|------|----------|------|
| 上传 | 0-10% | 文件上传到服务器 |
| 模型加载 | 10-30% | 加载 Whisper 模型 |
| 说话人分离 | 30-40% | pyannote 或简单分割 |
| 语音识别 | 40-80% | Whisper 转录音频 |
| 文本优化 | 80-90% | GLM-5 优化逐字稿 |
| 生成纪要 | 90-100% | 生成飞书风格纪要 |
